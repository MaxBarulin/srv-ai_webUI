# Исходники презентации

`../presentation.pptx` собирается скриптом, а не правится руками — так проще
менять цифры и порядок слайдов, не разбирая XML.

Три сборки из одних и тех же кадров:

```bash
cd docs/presentation-src
node build.js          # → ../presentation.pptx         (полная колода)
node build-short.js    # → ../presentation-short.pptx   (короткая, на пять минут)
node build-html.js     # → ../presentation.html         (одностраничник для чтения)
```

Оформление обеих колод — палитра, мастера слайдов, типовые слайды — лежит в
`deck.js`. Правится там, а не в файлах сборки: иначе полная и короткая колоды
разъезжаются по виду, и это замечают, когда обе уже на экране.

Нужен `pptxgenjs` (`npm i pptxgenjs`). Кадры интерфейса лежат в `shots/`;
снимаются на стенде с демонстрационными данными, ширина 1960.

**PPTX (полная).** Структура: титул → блок I «для руководства» → блок II «для технических
специалистов» → что дальше. Блоки разделены слайдами-заставками, чтобы
показывать только нужную половину.

**PPTX (короткая).** Восемь слайдов, около пяти минут: что это, рабочий цикл,
устройство, запас на будущее, что проверено, цели и эффект, что дальше. Цифры
целей и экономического эффекта взяты из паспорта проекта ПС — при правке
паспорта править и здесь. У каждого слайда в заметках докладчика записан
хронометраж и на чём делать упор.

**HTML.** Длинная страница со всеми кадрами и разделом «Как это устроено».
Самодостаточна: шрифты и картинки вшиты в base64, открывается с диска без сети.
Блоков «для руководства / для техников» в ней нет — это формат для чтения.

При смене цифр проверить во ВСЕХ файлах:
- слайд «Производительность» — токены/с;
- слайд «Модель» — параметры запуска llama.cpp;
- слайд «База знаний» — включён ли RAG;
- число автоматических тестов;
- в короткой колоде — цели, сроки и экономический эффект из паспорта проекта.
